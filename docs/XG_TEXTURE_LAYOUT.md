# XG texture computer ABI research and host texture-layout bridge

**Status:** read-only game call-site analysis and independently verified Windows host texture copy/format processing. The two actual Xbox `xg_xs.dll` imports remain **unresolved**. The host swizzle is **not** a console swizzle.

The original [repeatable read-only XG PE call-site probe](XG_CALLSITE_PROBE.md)
now verifies the two actual IAT locations, both FF25 import jump stubs,
and all six E8 relative-call candidates directly from the original title's
executable PE sections. Its `xg-context` mode extracts bounded 96-byte
pre-call and 48-byte post-call PE sections for local, independent disassembly,
verifies each call still targets an XG thunk, and rejects invalid ranges. Its generated synthetic scanner fixture is separately
testable using `ScarlettVI.exe xg-calls-fixture`. The new [descriptor evidence notes](XG_DESCRIPTOR_EVIDENCE.md)
summarize preliminary title-local field transfers derived from independent
read-only disassembly. These are **not** an Xbox XG ABI definition, and neither
Xbox graphics import is bound. The independent [synthetic field-projection fixture](XG_FIELD_PROJECTION.md)
validates five observed compact-to-prepared transfers and category-dependent
constants and known zeroed fields across three corroborated paths on 512
generated cases and 256 lookup-index cases, without inferring unknown
format/swizzle behavior.

## What the user-owned executable shows

Independent read-only analysis of `game_scarlett_master.exe` found four direct calls to the `XGCreateTextureComputer` trampoline at RVA `0x5F3FF40`:

| Call address (VA) | Observed behavior |
| --- | --- |
| `0x140344235` | RCX points to a prepared descriptor, RDX to a local output pointer; a returned-object method at vtable offset `+0x50` is used |
| `0x140979C75` | RCX points to a stack descriptor; RDX points into an allocated output object; returned HRESULT checked |
| `0x1416F7141` | RCX points to a descriptor copied into local stack storage, RDX to an output pointer; the caller processes texture format/dimensions |
| `0x145121A5E` | RCX points to a prepared descriptor; RDX to an output pointer; HRESULT checked and returned-object vtable methods invoked |

Two direct calls to `XGSuggestSwizzleMode` appear at `0x140C4B3CE` and `0x144ECCCA2` in routines working with texture format fields. Their full arguments, layout flags, true swizzle enumerations and error behavior are **not established**. The new [indirect-call candidate survey](XG_VCALL_SURVEY.md) records five
post-creation calls with `+0x08`, `+0x10` and `+0x50` displacements.
A vtable pointer does not prove that its Xbox object implements a standard
Windows COM interface. Neither Xbox import is bound to guessed host behavior.

## Public documentation for context, not a binary ABI guarantee

Microsoft describes XG as providing texture address-computation and tiling functions, including swizzling block-compressed texture payloads for Xbox hardware. Its public tools distinguish Xbox Series layouts from conventional Windows texture layouts.

- [Microsoft Xbox DirectXTex tiling sample](https://github.com/microsoft/Xbox-ATG-Samples/blob/main/Kits/DirectXTex/DirectXTexXboxTile.cpp)
- [DirectStorage Texture Shuffling sample](https://learn.microsoft.com/en-us/samples/microsoft/xbox-gdk-samples/directstoragetextureshuffling/)
- [xtexconv sample documentation](https://learn.microsoft.com/en-us/samples/microsoft/xbox-gdk-samples/xtexconv/)

No game assets, proprietary console SDK headers or code from the samples are copied into ScarlettVI.

## Original host-side implementation

`src/gpu/texture_layout.{h,cpp}` implements a **reversible synthetic** 8 × 8 Morton microtile format across array layers, mip chains and DXGI format elements:

| Host format | Element extent | Bytes per element |
| --- | --- | ---: |
| R8_UNORM | 1 × 1 texel | 1 |
| R8G8B8A8_UNORM | 1 × 1 texel | 4 |
| BC1_UNORM | 4 × 4 texels | 8 |
| BC3_UNORM | 4 × 4 texels | 16 |
| BC5_UNORM | 4 × 4 texels | 16 |

It validates dimensions, mip counts, array layers, sizes and overlapping storage, computes tightly packed linear rows, and zero-fills padding in the synthetic tile order. **That order is not Xbox XG, RDNA2 tile swizzle or Xbox texture-descriptor translation.** The [real GPU compute detiler](GPU_TEXTURE_DETILE.md) now converts this host-only layout on actual D3D12 hardware and returns exact linear bytes across 20 shader dispatch submissions.

The new `gpu-texture-layout` CLI mode runs:

- **CPU tests:** 130 subresources across five formats, four sizes including odd dimensions, mip chains and two array layers, comparing all **211,460 generated bytes** after reversible microtile conversion.
- **Real D3D12 tests:** 40 GPU subresources (five formats, four mips, two layers) uploaded through native `GetCopyableFootprints` row pitches into actual default-heap textures and read back through five real D3D12 queue submissions; every valid element is verified.
- **Negative checks:** unknown format, invalid dimensions/mips, oversized requests, undersized buffers and overlapping source/destination storage are rejected.

One D3D12 footprint subtlety emerged: `GetCopyableFootprints` can report a total buffer size ending after the final **valid** row bytes, rather than an additional full padded row. The correct bounds formula is `(rows - 1) * RowPitch + rowBytes`. This is now covered by the real GPU fixture. See the [public D3D12 documentation](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12device-getcopyablefootprints).

Run from the project directory:

```powershell
.\build\x64\Release\ScarlettVI.exe gpu-texture-layout
.\build\x64\Release\ScarlettVI.exe gpu-texture-detile
```

## Remaining steps

To link `XGCreateTextureComputer` safely, independently verify all Xbox input descriptor fields, output object methods and lifetime rules, supported XG swizzle-mode enumerations, hardware tile-addressing and error semantics. A future adapter can then translate from the **real** Xbox texture layout into this tested host format/footprint pipeline.

The historical texture-layout milestone had **25 unresolved Xbox import references**. The current data-only readiness report has **9 unresolved Xbox imports**, still including both XG symbols, and **title execution blocked**. Nothing in this work executes or modifies the original game.
