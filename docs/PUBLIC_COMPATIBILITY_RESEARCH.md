# Public Xbox Series compatibility references and ScarlettVI integration plan

**Research date:** 2026-11-25. This inventory describes public projects, **not** verified compatibility with this user's game build. Every genuine console interface still requires a ScarlettVI-specific ABI contract and original synthetic verification.

## Relevant public sources

| Project | Public strengths / relevance | Integration limit |
| --- | --- | --- |
| [XCL](https://github.com/xcl-dev/xcl) | Its authors report working native Xbox Series title execution; its docs cover XMem, graphics, console DirectStorage, shader translation, audio, TLS and virtual filesystem. | GPL-2.0 licensed. Do not copy implementation code into ScarlettVI without proper licensing and a separately reviewed integration plan. Its supported-title table does not verify this GTA VI build. |
| [VIctory-Belobug-AMD](https://github.com/Belobug/VIctory-Belobug-AMD) | Public Rust AMD-focused VIctory fork, self-reported boot/menus/world rendering on RX 9070 XT, 3–5 FPS and visible rendering faults. | GPL-3.0-or-later. Its progress does not validate ScarlettVI or an NVIDIA implementation. [Comparison](VICTORY_REFERENCE_NOTES.md). |
| [ztrx](https://github.com/Zettrox/ztrx) | Public Rust NVIDIA-focused VIctory fork, self-reported boot and some gameplay on RTX 3050 at 1–3 FPS, with broken indirect lighting. | GPL-3.0-or-later. No code copied; performance and compatibility not independently reproduced. [Comparison](VICTORY_REFERENCE_NOTES.md). |
| [ScarlettX](https://github.com/Freminet/ScarlettX) | C++ experimental Xbox Series PE, D3D12, AcpHal and sample service adapters with synthetic tests. | Many components are partial, several tests remain failing; console-specific ABI assumptions are not automatically valid for ScarlettVI. Check code licensing before any reuse. |
| [Xbox2Windows](https://github.com/R0Y00/Xbox2Windows) | Public experiments document caller-argument shapes for XMem queries, Windows GPU/PE research and conservative error paths. | An experimental research notebook, not an Xbox compatibility contract. Confirm locally before binding. |
| [Microsoft DirectStorage for Xbox](https://learn.microsoft.com/en-us/xbox/gdk/docs/features/console/storage/directstorage/directstorage-overview) | Publicly documents Xbox `IDStorageFactoryX` / `X1` / `X2`, queues and distinct async semantics. | The Xbox factory is **not** the same COM interface as PC `IDStorageFactory`; direct export forwarding is unsafe. |

XCL's public handoff specifically reports an older middleware stack corruption caused by writing a 0x78-byte XMem working-set structure into a smaller buffer. ScarlettVI's new capability policy explicitly **does not write** a guessed output layout. The XCL project also reports importing console middleware with similar names; this is **not evidence that GTA VI boots or renders correctly here**.

## Current ScarlettVI blockers

From the original game build's **read-only readiness inventory** after the safe working-set failure-path change:

| Workstream | Pending import references | Concrete technical gate |
| --- | ---: | --- |
| Xbox APU and DSP (`AcpHal.dll` / `xapu.dll` / `chad.dll`) | 6 | [APU host heap](APU_HOST_MEMORY.md), [owned address translator](APU_ADDRESS_TRANSLATION.md), [SHAPE storage](APU_SHAPE_CONTEXTS.md), [partial HAL factory](APU_HAL_FACTORY.md) and [partial XAPU result FIFO](XAPU_QUEUE_HOST.md) are bound; actual DSP configuration returns E_NOTIMPL, command submission and guest CHAD processing remain (the original [CPU FIR filter](DSP_CPU_CONVOLUTION.md) now also has a tested [host-typed XAPU-to-DSP completion path](XAPU_DSP_INTEGRATION.md)) |
| Xbox texture/graphics (`xg_xs.dll`) | 2 | Guest texture-layout/swizzle ABI and shader interfaces remain unresolved; a separate [real DXIL GPU host detiler](GPU_TEXTURE_DETILE.md) now passes 20 generated texture readbacks, NOT Xbox XG swizzle |
| Xbox DirectStorage (`XCRDAPI.dll`) | 0 | [Partial guest COM factory](XBOX_DSTORAGE_FACTORY.md) provides real staging. A separate [host-only async file queue](XBOX_DSTORAGE_HOST_ASYNC.md) and [enqueue/submit scheduler](XBOX_DSTORAGE_SUBMIT_GATE.md) now do bounded Win32 I/O, completion tracking and half-capacity dispatch; the [guest-IID status array](XBOX_DSTORAGE_STATUS_ARRAY.md) can now track real host-read barrier completion, but guest queue/file/decompression requests remain unsupported |
| Xbox memory (`xmem.dll`) | 0 | [Partial host quota transfer](XMEM_TITLE_SYSTEM_TRANSFER.md) now binds `XMemTransferMemory` with real XMemAlloc quota admission; console physical partitions, GPU and sparse allocations are not integrated |
| **Total** | **8** | |

An unresolved-import count of 0 **would not** be an execution test or bootability guarantee. The runtime still lacks parts of D3D12_XS/RDNA2 resource and shader translation, audio hardware behavior, file system/process initialization, static TLS lifecycle and fault isolation.

## Implement in this order

1. **Memory transfer:** [title-observed direction 1, 2-MiB aligned host budget transfers](XMEM_TITLE_SYSTEM_TRANSFER.md) now operate against a real synchronized XMemAlloc admission ledger. Expand accounting to physical XMem pages, sparse VM, GPU backing and actual system allocation consumers before treating this as Xbox partition emulation; other transfer directions are deliberately rejected.
2. **Audio HLE:** [bounded host APU heap](APU_HOST_MEMORY.md) and [32-bit APU mappings](APU_ADDRESS_TRANSLATION.md) now pass allocation, alignment, round-trip, ownership and concurrent release tests. The [inspected-title SHAPE buffer family](APU_SHAPE_CONTEXTS.md) now has tested allocation/release; the [AcpHal guest object](APU_HAL_FACTORY.md) now has a tested host ring allocation/cleanup lifecycle; the [partial XAPU FIFO](XAPU_QUEUE_HOST.md) now has tested connections and result dequeue. The original [CPU FIR convolution core](DSP_CPU_CONVOLUTION.md) now executes [host-typed XAPU commands](XAPU_DSP_INTEGRATION.md) and queues checked actual processing receipts; next establish the real title's command and completion layouts before integrating the same work into `XApuEnqueueCommand`/CHAD rather than inventing guest packets; HAL `+0x10` configuration remains `E_NOTIMPL`. The owned host address map is not console physical APU RAM.
3. **DirectStorage:** the [partial Xbox factory](XBOX_DSTORAGE_FACTORY.md) now has real staging plus a separate [original bounded host asynchronous file-read queue](XBOX_DSTORAGE_HOST_ASYNC.md) with exact bytes, errors, FIFO and factory staging lease. The [host submission gate](XBOX_DSTORAGE_SUBMIT_GATE.md) now models deferred Enqueue, explicit Submit, cancellation of unsubmitted work and half-capacity auto-dispatch. The [status-array COM interface](XBOX_DSTORAGE_STATUS_ARRAY.md) is now bound through the corrected guest factory virtual slot `+0x28` and aggregates real first-error host barriers. Next verify Xbox queue/file object vtables, game request packet format, guest status/fence submission, bounded virtual filesystem and decompression before exposing guest queue methods. Never use fake-success guest queues.
4. **Graphics:** the new [real DXIL host texture detiler](GPU_TEXTURE_DETILE.md) converts generated Morton tiles and passes 20 actual GPU submissions. Next implement genuine guest XG object interfaces and verified RDNA2 texture/GFX10 swizzle with real descriptor rules, then RDNA2 shader ISA translation and GPU command semantics; do not pretend the host layout is Xbox XG.
5. **Real execution gate:** [generated PE64 and DLL lifecycle fixtures](SYNTHETIC_PE_ENTRY.md) now pass import binding, forced relocations, generated process attach/detach callback ordering and private host TLS data for managed threads. Continue with genuine guest compiler TLS/TEB semantics, automatic DLL dependency initialization, process environment and fault isolation before any change to the actual title execution safeguard.

Keep the original proprietary build entirely outside the ScarlettVI source tree and read-only. No proprietary binaries or SDK headers belong in Git.
